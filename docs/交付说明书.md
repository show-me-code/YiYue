## 1. 它是什么

上传一篇 PDF，用**你自己的 LLM API**（OpenAI 兼容 / Anthropic 协议均可）把它翻成中文，
并**尽量保住原版版式**；然后在浏览器里双栏对照阅读。

关键差异：对 arXiv 论文，**不"照着 PDF 重新排版"，而是拿作者的 LaTeX 源码、只把文字换成中文、
用作者自己的模板与样式重新编译一遍**。因此公式编号、图表、交叉引用（图 1～图 9、附录 A/B/C）、
参考文献编号、"图/表/参考文献/摘要"这类自动标签，都随 LaTeX 一起自动正确。

任意 PDF（书、报告、无源码的论文）走 **BabelDOC 原位排版**引擎；arXiv 源码不可用或编译失败时
自动回退到它，并在任务备注里写明原因。

## 2. 快速上手

### 2.1 一键启动

```text
Windows：双击项目根目录的 启动译阅.bat
macOS / Linux：scripts/start.sh
```

启动器会：安装依赖 → 构建前端 → 应用 BabelDOC 排版补丁 → 清理残留端口 → 起服务 →
等就绪 → 打开浏览器 **http://127.0.0.1:8000**。已运行时再次双击会直接打开页面。
关闭窗口即停止服务。排查用日志：`backend/data/launch.log`。

### 2.2 首次配置（3 步）

1. 左侧「API 配置」→ 新增：填 Base URL（如 `https://api.deepseek.com/v1`）、API Key、模型名，点「测试连接」。
2. 「翻译任务」→ 拖入 PDF **或只填 arXiv ID**（如 `1610.01714`）→ 选配置 → 可选调行距 → 「开始翻译」。
3. 完成后进入双栏对照阅读器；也可下载「译文 PDF / 双语 PDF」。

> 只填 arXiv ID 时，应用会额外下载原版 PDF 作为"原文"栏与 ID 识别用，**翻译用的仍是 LaTeX 源码**。

### 2.3 没有 API Key 也能跑通全流程

```bash
# 终端 1：回声式 mock 翻译服务
uv run --project backend python scripts/mock_llm.py
# 终端 2：启动应用
scripts\start.bat
```

API 配置填 `http://127.0.0.1:8600/v1`、Key 任意、模型名 `mock-model`。

### 2.4 开发与测试

```bash
# 后端（含已构建前端）
cd backend && uv sync && uv run uvicorn app.main:app --port 8000
# 前端热更新（/api 代理到 8000）
cd frontend && npm install && npm run dev
# 测试
cd backend && uv run pytest -q            # 171 项
# tex 管线自检（无 LLM，几秒到一分钟，退出码即结论）
cd backend && uv run python ../scripts/check_tex_pipeline.py --src data/tasks/<id>/arxiv_src
```

> 首次使用 BabelDOC 会下载字体与版面识别模型（数百 MB）；侧边栏底部显示资产状态，可一键预热。
> Tectonic 编译器（约 21MB）在首次走 arXiv 路线时自动下载到 `backend/data/bin/`。

## 3. 功能清单

- **三种翻译引擎（混合路由）**：arXiv 源码直译（默认优先）／原位排版（BabelDOC）／自动（失败自动回退并备注）。
- **多配置档与多协议**：Base URL / API Key / 模型 / QPS；兼容 OpenAI、DeepSeek、GLM、SiliconFlow、
  one-api/new-api 中转、Ollama、LM Studio；支持 Anthropic 协议；「测试连接」自动探测协议给一键切换建议；
  每个任务开始前做一次真实调用预检，配置错误快速报错。
- **术语表**：手动维护 + CSV 导入导出，注入提示词保证译法一致；可选自动术语提取。
- **自定义系统提示词**：配置档里可写学术翻译规范，**两条引擎路径都会生效**。
- **翻译风格预设**：新建任务可选「默认（学术规范）／忠实直译／流畅润色／通俗易懂」，
  预设文本与配置档自定义规范合并后注入系统提示词，两条引擎都生效；风格计入缓存键。
  默认档自带中文学术写作规范（长句拆短、慎用「被」字句、避免「的」字堆叠、术语一致），
  即不选任何风格也不会得到逐字硬译的欧式中文。表单选项本地持久化，切页不丢。
- **双栏对照阅读**：左原文右译文、同步滚动缩放、可切「仅译文」；分段增量输出支持"翻完一段即可读"。
- **进度与队列**：SSE 实时进度、串行队列保护限流、取消/重试/删除、应用重启自动恢复中断任务。
- **翻译缓存**：文件哈希 + 选项哈希 + 管线版本，命中即秒出。
- **行距可调**：1.0×（与原版一致）～2.0×，默认 1.3×（中文排版惯例）。
- **闭环验证报告**：每篇产出自动逐页渲染、版心测量、内容完整性与语言残留检查，判定"通过/需人工复核"。
- **任务时间**：列表与阅读页显示完成时间（本地时区）与耗时。
- **AI 阅读助手（左侧边栏）**：顶栏开关控制，默认展开；多轮问答复用任务所属配置档，
  内置"总结论文／梳理论文大纲／生成学习指南／常见问题解答"一键模板，
  支持清空会话与复制回答（见 3.1）。
- **黑白主题切换**：阅读页顶栏 ☾/☀ 按钮切换深色/浅色，选择持久化到本地。
- **论文级任务卡片**：列表显示论文中/英文标题（arXiv 任务离线取自源码 `\title`，其余用文件名）
  与 LLM 自动总结的主题词标签；完成后后台生成，启动时回填历史任务。
- **归档**：任务卡片一键归档；侧边栏「归档」页集中展示，支持关键词搜索与主题词筛选。
- 闭环验证未通过的任务，状态标签显示为红色「已完成 · 需复核」。

### 3.1 逐段对照阅读 + AI 阅读助手

在"整页 PDF 双栏对照"之外，阅读页提供**按段落节奏的对照阅读模式**，并可在左侧
常驻 **AI 阅读助手**面板。两部分复用同一份译文数据与任务所属 API 配置档。

#### 逐段对照阅读

- 阅读页顶栏切换「逐段对照 / 双栏对照」；逐段视图按"英文段落在前、中文译文紧挨其下"的节奏
  连续排布，无卡片无隔断，工具栏可开关「显示原文」；**阅读区底色可选**：
  跟随主题 / 纸白 / 羊皮纸 / 护眼绿（护眼向配色，选择本地持久化）。
- **arXiv 任务走源码级抽取**（`tex_paragraphs.py`）：段落边界即 `.tex` 源码空行
  （不会被 PDF 文本块截断）；行内/展示公式保留 LaTeX 并由前端 **KaTeX** 排版渲染，
  作者自定义宏（`\newcommand`/`\DeclareMathOperator`）自动收集注入；`\cite` 家族按
  全文首次出现顺序编号为引用角标，`\ref/\eqref` 渲染为 § 角标（悬停见标签名）；
  导言区的 `\title`/`\author` 自动补为文首标题段与作者段。
- **插图内联到正确位置**：`figure` 环境的 `\includegraphics` 解析到作者源码里的实际
  图片文件（路径宏如 `\paperroot` 自动展开，缺扩展名时按 pdf/png/jpg 探测；子图环境
  自动剥离取主图注；`\iffalse` 注释块不抽取），位图直接返回、PDF 矢量图渲染为 PNG
  缓存，插图只出现一次（中文区不重复配图），图注先英文后中文；
  `algorithm`/`algorithmic`/代码环境渲染为等宽代码块（内部公式仍走 KaTeX）。
- **段落对齐用不变量锚点**（difflib 序列对齐）：图片路径、展示公式、引用编号、行内
  公式与数字在两种语言里逐字相同，先把两边锁定，区间内部再按相对位置配对——
  译文段被 LLM 拆分/合并、`\input` 子文件结构差异都不会造成错位；未配上的原文段
  保留显示，不丢内容。
- 无源码任务回退为 PDF 文本块抽取：先合并同列纵向紧邻的碎块（标题常被排成多个短块），
  过滤页眉/页脚/arXiv 打戳行；再取两边逐字相同的块（作者、邮箱、未翻译条目）作
  **锚点**分段，区间内按相对版面位置单调配对。
- 结果按任务缓存（`paragraphs.json`，随抽取算法版本与译文文件签名失效重建）；
  翻译进行中每批新页输出后自动追加新段落，"翻完一段即可读"。

#### AI 阅读助手（左侧边栏）

- 顶栏「AI 助手」开关控制左侧面板（默认展开）；问答**复用任务所属配置档**（OpenAI /
  Anthropic 协议均可），论文内容只发往用户自己配置的端点，不经过任何第三方。
- 多轮问答：系统提示注入论文正文上下文（原文段落，截断至 24k 字符），
  配置档里的自定义系统提示词同样生效；助手回复按 **Markdown + KaTeX** 渲染
  （列表/标题/代码块/表格/引用/链接/行内与展示公式）。
- 快速开始模板（一键提问）：总结论文、梳理论文大纲、生成学习指南、常见问题解答。
- 会话管理：**会话按论文持久化**（存任务目录 `chat_history.json`），重开阅读页自动恢复；
  历史对话默认折叠在顶部（点击展开/收起，滚轮上滑回看）；支持清空会话、复制回答；
  面板底部常驻"内容由 AI 生成，仅供参考"提示。

## 4. 架构与数据流

```
浏览器 Vue 3 + Element Plus + pdf.js
   │  REST + SSE（进度/状态） + Range（pdf.js 分片下载）
FastAPI（backend/app/main.py）
   ├─ api/      profiles · glossary · tasks · reader（段落/AI 问答）· files · assets · health
   ├─ services/
   │   ├─ orchestrator     串行队列、状态机、SSE 广播、引擎路由与回退、分段增量合并
   │   ├─ arxiv_engine     ID 检测、e-print 源码下载/解包/主文件定位、.bbl 对齐
   │   ├─ tex_translate    占位符保护 → 分块并发翻译 → 恢复 → ctex/行距/标签汉化
   │   ├─ tectonic         Tectonic 管理、编译、日志驱动修复
   │   ├─ verify           闭环版式验证（墨迹版心、溢出、内容完整性、语言残留）
   │   ├─ babeldoc_runner  唯一接触 BabelDOC 的隔离层 + 提示词/限流注入
   │   ├─ cache / pdfops / glossary / textio / timeutil
   │   └─ paragraphs / tex_paragraphs / chat  逐段对照抽取与对齐（PDF 块 / tex 源码）、AI 阅读助手问答
   └─ SQLite(data/app.db) + data/tasks/<id>/ + data/arxiv-cache/
```

一次 arXiv 直译任务的数据流：

```
提交 → 识别 arXiv ID →（无文件时下载原版 PDF）
 → 下载/解包 e-print 源码（tar.gz，含作者 .sty/.cls/.bbl/插图）
 → 逐候选主文件"试编译"（同时应用中文预处理，暴露环境问题）
 → 试编译通过 → 标注实际引擎 = arXiv
 → 逐文件：抽取图注/标题 → 保护公式命令引用 → 分块并发翻译 → 恢复 → 结构校验
 → 注入 ctex/行距/标签汉化 → 写回 → \bibliography 改写为 \input{*.bbl}
 → Tectonic 编译（失败则按日志定位坏文件，回退该文件为原文重试，最多 3 轮）
 → 闭环验证（逐页渲染 + 版心测量 + 内容完整性 + 语言残留）→ 落报告 + 判定
```

目录与产物：

| 路径 | 内容 |
|---|---|
| `backend/data/app.db` | SQLite：配置档、术语、任务、输出行 |
| `backend/data/tasks/<id>/original.pdf` | 原文（双栏阅读的左栏、ID 识别用） |
| `backend/data/tasks/<id>/mono.pdf` | 译文（无水印）；`dual.pdf` 为拼版双语 |
| `backend/data/tasks/<id>/arxiv_src/` | 下载并解包的作者源码（原始，未改） |
| `backend/data/tasks/<id>/arxiv_probe/main.pdf` | **编译基线**：同一份源码未翻译编译，版式对照基准 |

## 5. 核心设计一：arXiv 源码直译「五步法」

| 步骤 | 要求 | 实现 | 位置 |
|---|---|---|---|
| 1 | 拿作者源码，不照 PDF 抄 | 下载 `arxiv.org/e-print/<id>`，保留全部 `.tex`、作者 `.sty/.cls`、原始插图、**预编译 `.bbl`**；`.bbl` 与 `\bibliography{...}` 名字不一致时自动对齐并改写成 `\input{*.bbl}` | `arxiv_engine.py` |
| 2 | 骨架原封不动，只换文字 | 公式/命令/引用/图表/标签以 `[[M#]]` 占位符保护，正文与图注单独翻译成 `[[C#]]`；恢复时只替换占位符本身 | `tex_translate.py` |
| 3 | 解决中英混排 | Tectonic(XeTeX) + `ctex`(Fandol) 负责断行/禁则/中西文间距；行距可调（默认 1.3×，记录并还原作者 `\baselinestretch`）；自动标签汉化插在 `\begin{document}` 前，不被作者 `\renewcommand` 覆盖；样式里硬编码的 `Abstract` 补丁成「摘要」 | `tex_translate.py` |
| 4 | 保留原版"瑕疵" | 与"原始源码原样编译"的基线逐页比对，与基线一致的 Overfull/Underfull 判为作者原版特征，**不去修好** | `verify.py` |
| 5 | 闭环验证 | 逐页渲染 PNG + 墨迹版心测量 + 存疑页放大对照 + 内容完整性 + 语言残留 | `verify.py` |

唯一允许的 4 处结构性改动（都可审计）：
① 注入 ctex/Fandol 与行距块；② 自动标签汉化块；③ `\bibliography{x}` → `\input{x.bbl}`；
④ 编译不过时的日志驱动修复（xcolor 选项冲突 `\PassOptionsToPackage`、subfigure 垫片）。

## 6. 核心设计二：闭环验证怎么判定

### 6.1 判据（硬性不通过 vs 仅提示）

| 判据 | 口径 | 结论 |
|---|---|---|
| 新增超版心页 | 译文超版心、基线同页不超（按**页集合**取差） | 需人工复核 |
| 源码层 `\section` 命令数不一致 | 精确计数（剔除 `\sectionname` 之类宏名与注释） | 需人工复核 |
| 图表标题数少于基线 | 计数比对 | 需人工复核 |
| 成句英文残留（参考文献之前） | 与基线逐字相同者判为**插图/图片内文字**，只提示 | ≥3 行判需人工复核 |
| 图表标题仍为英文 | 已渲染到版面上的 | 需人工复核 |
| `\cite` / `\ref` 未解析 | 编译日志 | 需人工复核 |
| 未翻译正文块 | 累计涉及 **≥20 个英文词**才判问题，否则提示为"纯结构块" | 需人工复核 |
| 占位符漏进成品 | 分三类：**活代码里**残留 → 需人工复核；**仅注释行里** → 提示；**渲染 PDF 文本里**出现 → 需人工复核 | 见左 |
| 单块翻译超时 | 默认 300s/块（`YIYUE_CHUNK_TIMEOUT_S`） | 需人工复核 |
| 文件因编译失败回退英文 | `files_reverted` | 需人工复核 |
| 行距一致性显著低于基线 | 段内基线众数一致性 | 需人工复核 |
| 页数与基线不同 | 中文更紧凑属正常 | 仅提示 |
| 与基线一致的 Overfull | 作者原版瑕疵，忠实保留 | 仅提示 |
| 与基线版心偏差超阈值页 | 已生成放大对照图 | 仅提示 |

### 6.2 内容保真（"会不会丢内容"的实测答案）

对两篇论文共 12 个被翻译的 `.tex` 逐文件核对：

| 检查项 | 结果 |
|---|---|
| `\includegraphics`、`\label`、`\ref` 家族、`\cite` 家族、`\begin`/`\end`、章节命令、`\item`、`\footnote`、行内 `$…$` | 每个文件计数**完全一致** |
| 花括号配平 / 正文命令种类多重集 | 平衡 / 一致（无命令丢失、无凭空多出） |
| 占位符泄漏 | 成品源码 **0**、渲染 PDF **0** |
| 正文唯一改动 | `\bibliography{alain17a}` → `\input{alain17a.bbl}`（恢复 35 处引用） |
| 导言区新增 | 只有刻意注入块（见第 5 节 4 处） |
| 正文字符数 | 65,811 → 34,959（#4）、1,512 → 808（#8）：中文更紧凑，属预期 |

**按设计不翻译**（覆盖不到 ≠ 丢失）：导言区宏与注释、`table`/`tabular` **表格单元格内容**、
插图 PDF 内部文字、参考文献条目、作者姓名与单位、所有数学。

**可检出的降级**：某块两次校验不合格（会先拆半重试）或某文件编译失败时，该处保留英文原文，
必然计入验证报告并按上表判级——不会静默。

### 6.3 质量保障手段

- **171 项自动化测试**：单元 + mock-LLM 全链路集成；关键修复做过**变异验证**
  （把修复改回旧写法，对应用例确实变红）。
- **无 LLM 的确定性管线自检** `scripts/check_tex_pipeline.py`：回声翻译器跑真实源码的完整管线并真编译一次，
  输出主文件、`.bbl` 是否生效、占位符泄漏数、编译结果，退出码即结论。
- **源码层硬判据**：`\section` 命令数、占位符数量、`\item`/`\\` 数量、花括号与 `$` 计数。
- **真跑验收**：4 个任务全部 `engine_used=arxiv` 且判定「通过」（见第 8 节）。

## 7. 工程实现要点

| 主题 | 做法 |
|---|---|
| 占位符协议 | `[[M#]]` 保护片段、`[[C#]]` 图注/标题；恢复只替换占位符本身（绝不吞两侧花括号）；迭代展开嵌套占位符，且**只展开 M 命名空间**（否则图注 token 会被按 M 列表查成无关片段） |
| 单块校验 | 花括号/`$` 计数、占位符数量、`\item`+`\\` 数量、占位符邻位花括号、非"原样返回"；不通过→绕缓存重试→失败则递归拆分（半→四分之一）重试→仍失败保留原文并记录原因与英文词数 |
| 并发 | 分块翻译有界并发 `YIYUE_TRANSLATE_WORKERS`（默认 4，实测墙钟 ÷3.7）；进度回调只在主线程发；取消立即生效；统计局部收集后合并 |
| 超时 | 单块墙钟上限 `YIYUE_CHUNK_TIMEOUT_S`（默认 300s，超时打印全线程栈便于定位） |
| 编码 | `textio`：UTF-8 优先、失败退 cp1252/latin-1 的无损解码 + 统一换行 + UTF-8 写回（`errors="replace"` 会把重音字母永久改成 `�`） |
| 缓存 | 文件哈希 + 规范化选项哈希 + `PIPELINE_VERSION`；索引读改写加锁 + 唯一临时文件 + 原子替换；登记失败不影响成功产出 |
| 引擎标注 | `engine_used` 在**试编译通过时**即写入并广播；重试时清零，避免显示上一轮的旧引擎 |
| 安全 | CORS 只放行本机来源；tar 解包拒绝绝对路径/盘符/UNC/`..`/链接并加 `filter="data"`；文件接口路径越界校验；配置档连接测试只在有自定义 Base URL 时才跨协议试探（避免把 Key 发给另一家厂商） |
| 端口 | 启动器只结束**确认是本应用 uvicorn** 的残留进程，不误杀占用 8000 的其他程序 |
| 排版补丁 | `scripts/apply_babeldoc_patches.py` 对 BabelDOC 0.6.4 打 3 组补丁（孤儿片段重分配、垂直包含段落合并、行延伸墨迹裁剪+布局框排序），带"新串独有标记"的幂等判定 |

## 9. 运维手册

### 9.1 常见现象与处置

| 现象 | 原因 | 处置 |
|---|---|---|
| 双击启动"没反应" | 端口被残留进程占用 / 依赖缺失 | 看 `backend/data/launch.log`；启动器会清理**本应用**的残留进程；中文提示都在日志里（`.bat` 保持纯 ASCII 以免 cmd 按 GBK 解析乱码） |
| 任务备注出现「已自动回退原位排版引擎」 | 该论文源码不可用或编译失败（原因写在备注里） | 看任务目录下 `compile.log` / `main.log`；若属已知编译障碍（xcolor 冲突、subfigure 未定义）现已自动修复 |
| 任务长时间停在"翻译中"、进度不动 | 翻译服务被限流/单块过大：单块请求最长可等 300s 才放弃 | 调低配置档 QPS 后重试；被放弃的块会保留英文并计入报告 |
| 报告出现"需人工复核" | 见第 6.1 节的硬判据 | 按 `reasons` 定位；`render/` 逐页图与 `zoom/` 放大对照图可直接目检 |
| 页面显示旧译文 | 浏览器缓存（接口已带 `Cache-Control: no-store`） | 强制刷新；重跑会整体替换同一 URL 的文件 |
| 前端改动没生效 | 需要重新构建 | `cd frontend && npm run build`（开发时用 `npm run dev` 热更新） |
| 提示 BabelDOC 补丁未应用 | 依赖重装或引擎升级 | `cd backend && uv run python ../scripts/apply_babeldoc_patches.py` |

### 9.2 备份与清理

- 需要备份的：`backend/data/app.db`（配置/术语/任务索引）、`backend/data/tasks/`（产物）、
  `backend/data/arxiv-cache/`（源码缓存，可重建）。

## 10. 已知边界与局限（务必如实告知使用方）

1. **表格单元格内容不翻译**：`table`/`tabular` 环境整体受保护，以免模型改坏表格标记；
   表注（`\caption`）会翻译。若某篇表格内有成句英文必须翻译，需增加"表格内容也翻译"的开关，
   并配套更严的结构校验（当前未实现）。
2. **插图内部文字不翻译**：插图是作者原始 PDF/位图，按"保留原图"处理；图内英文会留在成品里，
   验证报告会把它识别为"与基线逐字相同"的图片文字并只作提示。
3. **参考文献条目不翻译**：沿用作者 `.bbl`/`.bib`（这是学术惯例，也保证引用编号正确）。
4. **导言区与作者信息不翻译**：宏定义、注释、作者姓名与单位保持原文。
5. **原位排版（BabelDOC）路径**是"版内翻译"，不重排版；复杂版式（双栏混排、艺术字）可能有轻微瑕疵。
6. **逐段对照的覆盖口径**（经词级审计实证：正文成句段落 0 丢失）：**表格单元格内容**、
   参考文献条目、插图内部文字不在阅读流中（可在双栏/原文 PDF 查看）；公式以 KaTeX 渲染，
   极少数作者宏无法展开时显示原始 LaTeX；透明环境（minipage 等）内嵌套的公式环境
   退化为纯文本。抽取按"不变量锚点"对齐，未配上的原文段保留显示、不丢内容。
6. **扫描件模式**为覆盖式方案（白底黑字假设），不是完整 OCR。
7. **单进程串行队列**：同一时刻只跑一个任务（保护限流）；大批量需排队。
8. **翻译质量取决于所选模型**：本仓库不内置模型；提示词已注入自定义规范与术语表，
   但术语一致性与文风仍受模型能力影响。
9. **AGPL**：BabelDOC 为 AGPL-3.0，对外提供网络服务需按 AGPL 开源。
10. **Windows 启动器**为纯 ASCII + CRLF 的 `.bat`；中文提示统一由 `scripts/launch.py` 输出。
